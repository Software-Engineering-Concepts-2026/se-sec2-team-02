1. "จากแนวคิด 'Software Entropy' และ 'Broken Window Theory' ลองมองย้อนกลับไปในโปรเจกต์ที่คุณเคยทำ มี 'หน้าต่างที่แตก' บานไหนที่คุณเคยปล่อยปละละเลย และมันส่งผลกระทบอย่างไรในระยะยาว?"
= ช่องโหว่ของหน้าต่างที่แตกที่ปลอยละเลยไว้ คือการที่ไม่ได้แยกระบบระหว่าง user ทั่วไป กับ ระบบของ receptionist(Admin) และจะส่งผลเสียอย่างร้ายแรงเกี่ยวกับ webapp และทำให้ระบบปนกันมั่วไปหมดจนเว็บพัง


2. "อธิบายหลักการ 'Take Responsibility' ในความเข้าใจของคุณ และยกตัวอย่างสถานการณ์ที่คุณจะนำหลักการ 'Provide Options, Don't Make Lame Excuses' ไปใช้ในการสื่อสารกับเพื่อนร่วมทีมในโปรเจกต์นี้"
= 'Take Responsibility' คือการยอมรับในการทำผิด กับตนเอง และกับเพื่อนร่วมทีม
  'Provide Options, Don't Make Lame Excuses' คือการใช้กับการกำหนดเวลาการทำงาน และการประชุมงาน หรือการปัดความรับผิดชอบและความผิดที่ได้กระทำของใครคนใดคนหนึ่งในทีม ในการหาทางออกร่วมกันในการแก้ไขปัญหาที่เกิดขึ้น
