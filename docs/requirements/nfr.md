# Non-Functional Requirements (NFR): Community Connector

เกณฑ์ด้านล่างต้องตรวจวัดได้ โดยใช้ข้อมูลทดสอบและเงื่อนไขเดียวกันในแต่ละรอบตรวจสอบ

## 1. Performance

- **NFR-01:** การค้นหาและกรองงานต้องตอบกลับภายใน **ไม่เกิน 2 วินาทีที่ p95** เมื่อมีข้อมูลจำลอง 1,000 รายการและผู้ใช้พร้อมกัน 50 คน วัดด้วยการยิงคำขอค้นหาอย่างน้อย 100 ครั้ง
- **NFR-02:** หน้ารายละเอียดประกาศต้องเริ่มแสดงผลภายใน **ไม่เกิน 3 วินาทีที่ p95** บนเครือข่ายจำลอง 4G และอุปกรณ์ระดับกลาง

## 2. Security

- **NFR-03:** รหัสผ่านต้อง Hash ด้วย bcrypt หรืออัลกอริทึมมาตรฐานที่เทียบเท่า และต้องมีความยาวอย่างน้อย **8 ตัวอักษร** ตรวจสอบด้วย Security Test ก่อน Merge
- **NFR-04:** Session ต้องหมดอายุและบังคับออกจากระบบเมื่อไม่มีการใช้งานเกิน **30 นาที** ตรวจสอบด้วย Integration Test
- **NFR-05:** ผู้ใช้ต้องเข้าถึงและแก้ไขได้เฉพาะประกาศหรือใบสมัครที่ตนเป็นเจ้าของหรือมีสิทธิ์เกี่ยวข้อง ตรวจสอบด้วยกรณีทดสอบ User A พยายามเรียกข้อมูลของ User B

## 3. Scalability & Availability

- **NFR-06:** ระบบต้องรองรับผู้ใช้พร้อมกันอย่างน้อย **100 คน** โดยคำขออย่างน้อย 95% สำเร็จและไม่มี HTTP 5xx ระหว่าง Load Test 10 นาที
- **NFR-07:** ระบบต้องมี Uptime ไม่น้อยกว่า **99%** ในช่วงเวลา 08:00–22:00 น. วัดจาก Health Check ทุก 1 นาทีเป็นเวลา 30 วัน

## 4. Usability

- **NFR-08:** ผู้ใช้ใหม่อย่างน้อย **4 จาก 5 คน** ต้องค้นหางานและสมัครงานสำเร็จภายใน **3 นาที** โดยไม่อ่านคู่มือ ใน Usability Test
- **NFR-09:** ฟอร์มสร้างประกาศต้องแสดงข้อความข้อผิดพลาดใกล้ช่องที่มีปัญหา และผู้ทดสอบอย่างน้อย **80%** ต้องแก้ไขฟอร์มได้โดยไม่ต้องขอความช่วยเหลือ

## 5. Maintainability

- **NFR-10:** โค้ดส่วน Utility และ Business Logic ใหม่ต้องมี Test Coverage อย่างน้อย **80%** ตรวจสอบด้วย `npm run test:coverage`
- **NFR-11:** การเปลี่ยนแปลงหนึ่ง Feature ต้องไม่ทำให้ Test ที่ไม่เกี่ยวข้องล้มเหลว และ Pull Request ทุกอันต้องผ่าน `npm run lint` และ `npm run build`
- **NFR-12:** เอกสาร Requirement ที่เกี่ยวข้องกับ Feature ต้องอัปเดตภายใน Pull Request เดียวกัน และต้องมีผู้รีวิวอย่างน้อย 1 คนก่อน Merge
