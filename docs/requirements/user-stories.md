# User Stories: Community Connector

### Story US-01: ค้นหางานตามตัวกรองช่วงเวลาและสถานที่

As a นันทิดา “แนน”
I want ค้นหาและกรองประกาศงานพาร์ตไทม์ตามช่วงเวลาว่างและสถานที่ใกล้ ม.พะเยา
So that สามารถเลือกงานที่ไม่กระทบเวลาเรียนได้

**Acceptance Criteria:**

- [ ] Given อยู่หน้าค้นหางาน When เลือกสถานที่ “หน้า ม.พะเยา” และเวลา “17:00–21:00 น.” Then ระบบแสดงเฉพาะงานที่ตรงเงื่อนไข
- [ ] Given ไม่พบงานที่ตรงเงื่อนไข When ระบบค้นหาเสร็จ Then แสดงข้อความ “ไม่พบงานที่ตรงกับเงื่อนไข” พร้อมปุ่มล้างตัวกรอง

**Priority:** Must  
**Estimate:** M

---

### Story US-02: ดูรายละเอียดประกาศงานและค่าตอบแทน

As a นันทิดา “แนน”
I want ดูรายละเอียดงาน หน้าที่ความรับผิดชอบ และอัตราค่าตอบแทน
So that ประเมินความเหมาะสมก่อนกดสมัครงาน

**Acceptance Criteria:**

- [ ] Given แนนเลือกประกาศงาน When หน้ารายละเอียดแสดงผล Then ต้องเห็นค่าตอบแทนและเวลาทำงานชัดเจน
- [ ] Given แนนอ่านรายละเอียดงานเสร็จ When เลื่อนถึงส่วนท้าย Then มีปุ่ม “สมัครงาน” แสดงอย่างชัดเจน

**Priority:** Must  
**Estimate:** S

---

### Story US-03: ยื่นสมัครงานพาร์ตไทม์

As a นันทิดา “แนน”
I want กดสมัครงานพร้อมแนบข้อมูลติดต่อและตารางเรียนเบื้องต้น
So that ผู้ว่าจ้างสามารถพิจารณาคุณสมบัติได้ทันที

**Acceptance Criteria:**

- [ ] Given แนนเข้าสู่ระบบแล้ว When กด “สมัครงาน” Then ระบบบันทึกใบสมัครและส่งข้อมูลให้ผู้ว่าจ้าง
- [ ] Given แนนยังไม่ได้เข้าสู่ระบบ When กด “สมัครงาน” Then ระบบแจ้งให้เข้าสู่ระบบก่อนและไม่สร้างใบสมัคร

**Priority:** Must  
**Estimate:** M

---

### Story US-04: ระบบอัปเดตสถานะประกาศงานเต็มแบบ Real-time

As a นันทิดา “แนน”
I want เห็นสถานะประกาศงานที่ปิดรับหรือคนเต็มแล้วทันที
So that ไม่เสียเวลาส่งใบสมัครในตำแหน่งที่รับคนครบแล้ว

**Acceptance Criteria:**

- [ ] Given ประกาศรับสมัครครบจำนวนแล้ว When แนนเปิดดูประกาศ Then ปุ่มสมัครเป็นสีเทาและแสดง “ปิดรับสมัครแล้ว”
- [ ] Given แนนกำลังสมัครในจังหวะที่คนเต็มพอดี When ระบบประมวลผล Then แจ้ง “ขออภัย ตำแหน่งนี้เต็มแล้ว” และไม่สร้างใบสมัคร

**Priority:** Should  
**Estimate:** L

---

### Story US-05: โพสต์สร้างประกาศรับสมัครงาน

As a พี่เอก  
I want สร้างประกาศรับสมัครงานพาร์ตไทม์ระบุเงื่อนไขและจำนวนรับ  
So that ได้นิสิตมาช่วยงานในร้านได้ทันเวลา

**Acceptance Criteria:**

- [ ] Given กรอกหัวข้องาน ค่าตอบแทน เวลา และจำนวนที่ต้องการครบ When กด “เผยแพร่” Then ประกาศแสดงในระบบ
- [ ] Given กรอกข้อมูลไม่ครบ When กด “เผยแพร่” Then ระบบชี้ช่องที่ต้องแก้และไม่สร้างประกาศ

**Priority:** Must  
**Estimate:** M

---

### Story US-06: จัดการและแก้ไขประกาศงาน

As a พี่เอก  
I want แก้ไขรายละเอียดข้อมูลในประกาศงานเดิมที่ลงไว้ได้  
So that สามารถอัปเดตข้อมูลเงื่อนไขให้ถูกต้องตรงกันเสมอ

**Acceptance Criteria:**

- [ ] Given พี่เอกเป็นเจ้าของประกาศ When แก้ไขรายละเอียดและกด “บันทึก” Then ข้อมูลใหม่แสดงแทนข้อมูลเดิมทันที
- [ ] Given พี่เอกแก้ไขเวลาเป็นค่าที่ไม่ถูกต้อง When กด “บันทึก” Then ระบบแจ้งข้อผิดพลาดและคงข้อมูลเดิมไว้
- [ ] Given มีนิสิตบันทึกหรือสมัครประกาศไว้ When พี่เอกแก้ไขเงื่อนไข Then ระบบแจ้งเตือนนิสิตว่าประกาศมีการอัปเดต

**Priority:** Should  
**Estimate:** S

---

### Story US-07: ตรวจสอบรายชื่อผู้สมัครและตอบรับเข้าทำงาน

As a พี่เอก
I want ดูรายชื่อนิสิตที่สมัครและกดตอบรับหรือปฏิเสธได้
So that สามารถคัดเลือกพนักงานพาร์ตไทม์ได้อย่างเป็นระบบ

**Acceptance Criteria:**

- [ ] Given มีผู้สมัคร When พี่เอกกด “ตอบรับ” Then สถานะเปลี่ยนเป็น “รับเข้าทำงาน” และแจ้งเตือนไปยังนิสิต
- [ ] Given มีผู้สมัคร When พี่เอกกด “ปฏิเสธ” Then สถานะเปลี่ยนเป็น “ปฏิเสธ” และแจ้งเตือนไปยังนิสิต
- [ ] Given ตำแหน่งเต็มแล้ว When พี่เอกพยายามตอบรับเกินจำนวน Then ระบบป้องกันการตอบรับและแจ้งเหตุผล

**Priority:** Must  
**Estimate:** M

---

### Story US-08: ดูประวัติการสมัครงานของตนเอง

As a นันทิดา “แนน”
I want ตรวจสอบสถานะและประวัติการสมัครงานทั้งหมดที่เคยยื่นไว้
So that ติดตามผลการคัดเลือกได้สะดวกรวดเร็ว

**Acceptance Criteria:**

- [ ] Given แนนเข้าสู่ระบบและเปิดหน้าประวัติการสมัคร When โหลดสำเร็จ Then แสดงงานที่สมัครพร้อมสถานะ รอพิจารณา/ตอบรับ/ปฏิเสธ
- [ ] Given แนนยังไม่มีประวัติการสมัคร When เปิดหน้าประวัติ Then แสดงข้อความที่เข้าใจง่ายและปุ่มไปหน้าค้นหางาน
- [ ] Given แนนเปิดรายการสมัคร When เลือกรายการหนึ่ง Then แสดงรายละเอียดประกาศและวันที่ส่งใบสมัคร

**Priority:** Should  
**Estimate:** S

---

## Feature Quality Bar Cross-check

ทุก Story ต้องผ่านคำถาม 4 ข้อนี้ก่อนเข้าสู่การพัฒนา:

- **Independent:** Story สามารถพัฒนาและทดสอบได้โดยไม่ต้องรวมงานที่ไม่เกี่ยวข้องหรือไม่
- **Coherent:** Story มีเป้าหมายและ Acceptance Criteria ที่สอดคล้องกันหรือไม่
- **Relevant:** Story แก้ปัญหาของ Persona และอยู่ในขอบเขตของ Proposal หรือไม่
- **Valuable:** เมื่อทำเสร็จแล้ว ผู้ใช้หรือทีมได้รับคุณค่าที่ตรวจสอบได้หรือไม่
